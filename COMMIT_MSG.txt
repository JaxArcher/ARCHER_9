Vision grounding fix, moondream CPU+pause gating, curated LOGS pane, voice/pipeline fixes

Two sessions' worth of fixes, summarized by area:

## Vision (core_agent.py, config.py, observer/person_id.py)

- Root-caused "camera feed isn't being seen" all the way to the actual
  cause: the plain `gemma4:e4b` Ollama tag is packaged TEXT-ONLY (no
  vision projector), despite Gemma 4's architecture supporting it.
  Confirmed via direct Ollama library research and a bare, ARCHER-free
  test request that still hallucinated ungrounded content.
- Switched core_primary_model default to `gemma4:e4b-it-qat`, the Ollama
  tag that actually bundles the vision+audio projector. Confirmed live:
  descriptions are now genuinely grounded in the real camera frame
  (correct scene structure, objects, layout), and first-token latency
  dropped from 55-84s to 13-15s as a bonus (smaller quantized model).
- Added hard proof-of-payload logging in _stream_local so "did the image
  actually get sent to Ollama" is answered by a log line instead of
  speculation.
- Rewrote the visual-description system prompt instruction to stop the
  model from treating every image as a repeat of a prior turn ("I see the
  same image again") and to answer the specific part of the scene asked
  about instead of generic filler -- without literally quoting bad
  example phrases in the prompt (a small/weak model echoing a quoted
  "don't say this" string back verbatim is a known failure mode).
- Fixed false-positive face detection flooding "unrecognized person"
  results: InsightFace was correctly detecting real faces rendered on a
  TV screen (a video-chat-style show grid) and reporting each one as an
  unknown visitor physically in the room. Added a minimum face-size-
  relative-to-frame + detector-confidence filter, and a hard cutoff that
  skips identification entirely when more than 3 faces appear in one
  frame (a screen/photo, not a room full of people).

## Moondream: CPU + cross-process pause gating

- Reverted moondream's observer Ollama instance back to CPU-only
  (previously moved to GPU on 2026-09-16 specifically to route around
  CPU/STT contention). GPU headroom matters more now; the contention risk
  is handled properly instead.
- Added a Redis-backed cross-process "is a live ARCHER session open" flag
  (RedisBuffer.mark_gui_active/is_gui_active, TTL-based so a crashed
  process doesn't leave the observer paused forever). server.py refreshes
  it every 3s while any browser client is connected.
- ObserverPipeline._analysis_loop now checks that flag and skips its
  whole CPU-heavy analysis cycle while ARCHER is in active use -- fixing
  a check that existed before (self._voice_pipeline_state) but had gone
  permanently dead once the observer became its own standalone OS
  process.
- ollama_bootstrap.py's _spawn_ollama_serve now takes a force_cpu param,
  used only for the observer instance.

## Browser "brain" model dropdown

- Manually switching the local model via the SYSTEM tab dropdown now
  auto-resets back to the configured default the moment the last browser
  client disconnects, so a one-off test pick (e.g. llama3.2-vision) can't
  silently keep running as the primary model -- including tool-calling --
  after the tab is closed and forgotten.

## LOGS pane: curated "what ARCHER is doing right now" feed

- Replaced the raw DEBUG-level log-file tail (mostly httpx polling noise)
  with a curated event-bus-driven feed: wake word, listening, heard text,
  camera/vision status, filler lines, response ready, errors, mode
  changes -- all human-readable, all reusing the existing log_line WS
  channel so no frontend protocol change was needed.
- Rewrote web/js/logs.js to render each event as its own styled row
  (dimmed timestamp + colored message) instead of one flat text dump, and
  added a live "Working for Xm Ys" header while ARCHER is actively
  processing or speaking, plus a 50-line history buffer so a freshly
  opened tab isn't blank.
- Removed the "Unrecognized People" pane from the MEMORY card per Col's
  call -- backend queueing in person_id.py/pending_person_confirmations
  is untouched in case a future UI wants it.

## Voice pipeline / TTS / camera (earlier this session)

- Fixed Ollama 400 errors on visual turns: gemma-family models reject
  requests carrying both "tools" and "images" together -- tools are now
  omitted for any round that has an image attached.
- Fixed the voice pipeline double-invoking _process_utterance after both
  the silence-triggered and 30s-hard-timeout paths, which was causing a
  spurious "supersede" on otherwise-normal turns.
- Fixed TTS dropping the first sentence of every response (an
  unconditional cancel() at turn start was never cleared before the next
  turn's synthesis) via a new TTSService.reset_cancel().
- Fixed WebcamCapture.stop() leaving a stale frame available forever
  after the camera is released for barehands gesture control -- now
  clears the cached frame and timestamp too.
- Added automatic session-log mirroring to
  docs/reports/latest_session_log.log (overwritten each run) so Col no
  longer has to manually copy/paste console output for debugging.
